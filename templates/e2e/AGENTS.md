# Working in this e2e repo

Read before changing anything. This repo carries the CROSS-APP suites for a workspace pair; it owns no application code and no runtime services.

## The rules with teeth

1. **The registries are the single source.** A scenario exists when `src/flows/cases.ts` has its case AND `src/flows/*.flow.ts` has its implementation under the same quoted id — `pnpm registry:verify` fails either half alone. A contract expectation exists when `src/contract/cases.ts` registers `{id, operationId, request, expectation}`; the operationId must exist in the workspace's contract. Never write a test directly into a spec file — the specs are generated loops over the registries.
2. **`test:e2e` is not in `verify`, and must stay out.** The static gates are offline and deterministic; the runtime suites need the pair the WORKSPACE provides (`pnpm ws:up` there, or `E2E_WEB_URL`/`E2E_API_URL`/`E2E_CONTRACT`). Unreachable services skip locally and fail under CI=1 — do not "fix" a skip by weakening `e2e/support/services.ts`.
3. **The validator is byte-pinned.** `scripts/validate-lib.mjs` is part of the seed (sha256 in `.proto-forge/seed.lock`); loosening it to make a red contract run green is tamper, and a hook blocks the edit. Growing the schema subset is an ADR + `pnpm seed:lock`.
4. **The prompt log is append-only**; locks and snapshots are generated (`pnpm snapshot`, `pnpm seed:lock`). Relaxing a mandatory gate (`registry`, `stub`, `snapshot`, `status` — the `MANDATORY_GATES` list in `scripts/config.mjs`) needs a live waiver — reason, ADR, expiry — or it runs at `error` regardless.
5. **Every commit names its model, and every dispatch is routed.** The `prepare-commit-msg` hook derives the `Co-Authored-By` trailer from the cited entry's `model:` and `commit-lint` refuses any other identity (BR-46). Each `.prompts/` entry carries `model: <registered id or alias from .proto-forge/models.json>` — read yours from `.proto-forge/session.json` (the `SessionStart` / `PostModelSwitch` hooks write it) or `PROTO_FORGE_MODEL`, never guess it. An entry written for a dispatched subagent adds `delegated-by: <your entry id>` and `activity: <routing-table key>`, and the subagent runs on the tier the table routes that activity to; a frontier-tier orchestrator delegates only to a strictly cheaper tier, no override, and a deliberate deviation from the routed tier records `routing-override: <reason>`. `prompt:lint` enforces it, and the registry copy is a protected path edited only in the plugin (BR-50, NFR-31).
6. **Zero runtime dependencies.** `@playwright/test` and the TS/eslint toolchain are the whole surface; a new dependency is an ADR-worthy event.
7. **The documented status is a derivation.** `docs/STATUS.md`'s block between the quality markers is generated by `pnpm quality:report` from the registries and the verify chain; the `status` gate re-renders it byte-wise. Never edit the block by hand — change the source and regenerate.

## When verify is red: `pnpm heal`

`pnpm heal` works a red `pnpm verify` in three bounded tiers. Tier 1 (default on, 2 passes) replays the deterministic regenerations from the healing registry — in this template only the STATUS block (`quality:report`); a registry/implementation disagreement is a decision and deliberately has no recipe. Tier 2 dispatches a bounded agent pass and runs **only** with `selfHealing.agent.enabled: true` in the committed config: committing that flag is the operator's standing, reviewed consent, exactly like `autoPropagate`. Tier 3 prints a blocked report and exits 1. Hard-stop gates never enter any tier, and every pass writes a `.prompts/` entry before it acts.

## Commands

`pnpm verify` is the bar (static, offline). `pnpm test:e2e` against the workspace pair. `pnpm gates:selftest` after touching any script in `scripts/`. `pnpm doctor` on a fresh machine — toolchain pins, husky wiring, installed tree vs lockfile, playwright browsers, the `E2E_*` surface; every ✗ prints its fix. `pnpm quality:report` / `pnpm status:verify` regenerate / verify the derived quality facts.
