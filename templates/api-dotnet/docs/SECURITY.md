# Security

The service is treated as internet-facing from commit one. Controls are enforced by gates (`pnpm sec:scan`, `pnpm log:scan`, ArchUnitNET + arch:verify) and by the byte-pinned platform kernel, not reviewer memory (BRS §16).

## Application controls

- **Input validation** — every external input crosses a validated boundary: the create payload against the domain's `System.ComponentModel.DataAnnotations` constraints inside the service, path parameters by type conversion before any handler runs, the environment through `App.Config.AppOptions.FromEnvironment()`. An unvalidated field never reaches a handler.
- **Error responses leak nothing** — every client-visible failure is a registered RFC 9457 problem type (`App.Platform.Problems`); an unexpected throw is mapped to the generic `internal` problem by the kernel's `ProblemHandlerMiddleware`, and the cause goes to the structured log, never the response.
- **Security headers** — the kernel's middleware sets them on every reply (`App.Platform.SecurityHeadersMiddleware`): `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `X-Frame-Options: DENY`, `Cache-Control: no-store`, and a `default-src 'none'` Content-Security-Policy for the JSON API. TLS termination and HSTS belong to the deployment edge — no local server speaks TLS.
- **Structured, redacting logging only** (NFR-12) — production code logs through the kernel's `AppLogger` (`Microsoft.Extensions.Logging` behind a redacting key/value renderer); `log:scan` fails a bare `Console.Write`/`Console.Error`, a `Debug.Write`/`Trace.Write` dump, a `Microsoft.Extensions.Logging` import outside `src/App/Platform`, and any log-call key named like PII (`password`, `token`, `authorization`, …).
- **Secrets** — none in the repo. Config via environment variables read in one place (`AppOptions`); `gitleaks` scans the whole tree including `.prompts/`.
- **SQL** — all persistence goes through EF Core's parameterised queries in `App.Adapters.Out.Persistence`; the only literal SQL is inside the append-only migrations in `src/App/Adapters/Out/Persistence/Migrations/`, and it is never built from a runtime value.

## Supply chain (BRS §4.2)

- Two lockfiles committed and enforced (NFR-08/NFR-11): `src/App/packages.lock.json` and `tests/App.Tests/packages.lock.json` (`RestorePackagesWithLockFile` in `Directory.Build.props`; CI restores with `--locked-mode`, so a resolution the lock does not name fails) under the **SDK band pinned in `global.json`**, and `pnpm-lock.yaml` (`--frozen-lockfile` in CI) for the gate corpus. The two local tools — `dotnet-ef` and `dotnet-stryker` — are pinned to exact versions with `rollForward: false` in `.config/dotnet-tools.json`.
- **Dependency budget** (NFR-13): `deps:budget` holds the declared runtime surface to a named allowlist (ASP.NET Core rides the framework reference; the one shipped package is the Postgres EF provider) under a ceiling of 10.
- **osv-flagged transitive pins** (each annotated with its advisory id): `SSH.NET` ≥ 2026.0.0 in `tests/App.Tests/App.Tests.csproj` (HIGH GHSA-q939-rpr3-3284, reached through Testcontainers). A direct pin of the patched release keeps the audit clean without suppressing the restore warning; drop it once the carrying package catches up.
- **Audit**: `sec:scan` runs osv-scanner over the locked NuGet graph (`src/App/packages.lock.json`) — the same pinned resolution CI restores — and `pnpm sbom` derives a deterministic CycloneDX 1.5 SBOM from that same lockfile (`.proto-forge/sbom.cdx.json`, `pkg:nuget/…` purls, purl-sorted, no timestamp, content hashes carried through) as the attested artefact. The lockfile is the audit input rather than the SBOM because every scanner build understands a lockfile while SBOM ingestion is version-dependent, and a gate that only works on the scanner version you happen to have is not a gate. Findings are a hard stop, never auto-suppressed. gitleaks and osv-scanner are external binaries: enforced when present, warned locally when absent, mandatory in CI (the §19 gitleaks precedent).
- **Seed integrity (BRS §17.2)**: `.proto-forge/seed.lock` pins the platform kernel (`src/App/Platform/**`) and the gate corpus (`scripts/**`) by one sha256; `snapshot:diff` re-verifies it every run. Upgrades are explicit (`pnpm seed:lock` + ADR), and a local hook blocks kernel edits before they land.
