# Quality status

This page carries the derived facts of the workspace repo: how many parts the
manifest declares, how many are materialized in this checkout, and which gates
stand in the `pnpm verify` chain. Nothing between the markers is typed by hand
— the table is regenerated by `pnpm quality:report` from
`.proto-forge/quality.json`, which is itself derived from `workspace.json`,
the tree and `package.json` during `pnpm verify`, and the mandatory `status`
gate fails the build the moment this document, the derived facts and their
sources disagree. The present-count is machine state on purpose: a freshly
cloned workspace legitimately has zero parts on disk, and the diff of this
file shows each part arriving. The parts' own quality lives in the parts:
each carries its own STATUS.md, refreshed by its own verify. There are no
dates on this page: freshness is not a timestamp, it is the bond to the same
verify run.

The counts in the table are mirrors, not sources: the part declarations live
in `workspace.json` (held to the tree and the gitignore by `ws:verify`), and
the gate chain in `package.json`'s `verify` script. `pnpm status:verify`
re-reads all of them and fails when a mirror and its source drift apart, so
the one command that refreshes everything is a full `pnpm verify` — or
`pnpm quality:report` alone.
