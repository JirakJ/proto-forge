# Quality status

This page carries the derived quality facts of the suite repo: how many flow
and contract cases the committed registries declare, and which gates stand in
the `pnpm verify` chain. Nothing between the markers is typed by hand — the
table is regenerated by `pnpm quality:report` from
`.proto-forge/quality.json`, which is itself derived from the registries and
`package.json` during `pnpm verify`, and the mandatory `status` gate fails the
build the moment this document, the derived facts and their sources disagree.
The runtime pass/fail numbers deliberately do NOT live here: `pnpm test:e2e`
needs the running pair, and that job — with its own reporting — belongs to the
workspace repo's orchestration. There are also no dates on this page:
freshness is not a timestamp, it is the bond to the same verify run — when a
number changes, the diff of this file shows it.

| measure | value | enforced by |

Gate chain: config:check → gates:selftest → lint → typecheck → registry:verify → stub:scan → adr:lint → prompt:lint → snapshot:diff → quality:report → status:verify
<!-- quality:end -->

The counts in the table are mirrors, not sources: the case counts live in
`src/flows/cases.ts` and `src/contract/cases.ts` (held to their
implementations and to the contract by `registry:verify`), and the gate chain
in `package.json`'s `verify` script. `pnpm status:verify` re-reads all of them
and fails when a mirror and its source drift apart, so the one command that
refreshes everything is a full `pnpm verify` — or `pnpm quality:report` alone.
