# proto-forge e2e layer

The cross-app test layer scaffolded by the `proto-forge` skill for a multi-part workspace (T14): a Playwright + TypeScript repository that sits INSIDE the workspace next to `api/` and `web/`, and proves the RUNNING pair honours the promises each part made on its own.

If you are an agent working in this repository, read **`AGENTS.md`** first.

## Run

```bash
pnpm install
pnpm exec playwright install chromium
pnpm verify                     # every STATIC gate, fail-fast, offline
pnpm test:e2e                   # the runtime suites — needs the pair (see below)
```

`pnpm test:e2e` is deliberately **not** part of `verify`: it needs the running pair, which this repo does not own. From the workspace repo, `pnpm ws:up` starts the api (compose) and the built web preview and prints the URLs; then:

```bash
E2E_API_URL=http://localhost:3000 E2E_WEB_URL=http://localhost:4173 pnpm test:e2e
```

Unreachable services (or an absent contract) SKIP the affected tests locally with a note naming the fix, and HARD-FAIL under `CI=1` — the e2e-against-pair CI job belongs to the WORKSPACE repo's orchestration, which brings the pair up first; this repo's own CI runs the static `verify` only.

## The two suites

**Cross-app flows** (`e2e/flows.spec.ts`): scenarios derived from the brief's flows facets at generation time, driven through the real web UI against the real api. The registry `src/flows/cases.ts` is pure data; implementations live in `src/flows/*.flow.ts` keyed by case id (the shipped Note demo: create → list → delete). One test per case, generated by a loop.

**Consumer-driven contract** (`e2e/contract.spec.ts`): for each case in `src/contract/cases.ts` `{id, operationId, request, expectation}`, replay the request against the live api, assert the status, and validate the response body against the contract's response schema for that operation+status. The contract is the backend's locked artifact, resolved through the workspace manifest (`../workspace.json` → `contract.source`), overridable with `E2E_CONTRACT=/path/to/openapi.json`.

Response validation is a dependency-free structural JSON-schema-subset validator (`scripts/validate-lib.mjs`, typed facade `src/contract/validate.ts`): type, required, properties, items, enum, const, `additionalProperties: false`, min/max length, pattern, format-lite (uuid, date-time), in-document `$ref`, anyOf/oneOf. Features outside the subset are ignored, never mis-enforced; the gates-selftest proves every rule rejects what it claims to.

## Gates (all static, all in `verify`)

| Command | What it proves |
| --- | --- |
| `pnpm config:check` | The config + waivers are honest (mandatory gates: `registry`, `stub`, `snapshot`, `status`) |
| `pnpm gates:selftest` | Every gate, hook and the validator still reject what they claim to |
| `pnpm lint` · `pnpm typecheck` | strictTypeChecked eslint (api-node's bar, minus boundaries) + tsc |
| `pnpm registry:verify` | Registries parse; ids unique + kebab-case; every flow case implemented and vice versa; specs still consume the registries; every contract case's operationId exists in the referenced contract when reachable (pre-workspace absence = a note) |
| `pnpm stub:scan` | No placeholder markers, first-party mocks or gated-rule escape hatches in src/ or e2e/ |
| `pnpm adr:lint` · `pnpm prompt:lint` | ADR ledger anchored + append-only prompt log well-formed |
| `pnpm snapshot:diff` | Structure matches the committed snapshot; the gate corpus (validator included) matches seed.lock |
| `pnpm quality:report` · `pnpm status:verify` | `docs/STATUS.md`'s block is a derivation of the registries + chain (`.proto-forge/quality.json`), byte-checked |

Support tools outside the chain: `pnpm doctor` (fresh-machine pre-flight — toolchain pins, husky wiring, installed tree vs lockfile, playwright browsers, the `E2E_*` surface; every ✗ prints its fix) and `pnpm heal` (tiered self-healing for a red `verify`: mechanical regenerations first, a consent-gated agent pass second, escalation third — bounded, hard-stop gates excluded, every pass prompt-logged; `docs/TROUBLESHOOTING.md`).

## Layout

```
src/flows/cases.ts        flow registry — pure data, one scenario per flows facet
src/flows/notes.flow.ts   demo implementations keyed by case id (the pattern)
src/contract/cases.ts     contract registry — one consumer expectation per case
src/contract/validate.ts  thin typed facade over the shared validator
e2e/flows.spec.ts         generated flow suite (one test per registry case)
e2e/contract.spec.ts      generated contract suite (replay + schema validation)
e2e/support/services.ts   the tool-gating policy: skip locally, fail in CI
scripts/                  the gate corpus (byte-pinned), incl. validate-lib.mjs
docs/adr/                 ADR ledger · .prompts/ append-only prompt log
.proto-forge/             config + facets (pairedBrief) + snapshot + seed.lock
```
