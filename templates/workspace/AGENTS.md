# Working in this workspace repo

Read before changing anything. This repo is small on purpose: the manifest, the shared brief record and the orchestration scripts. The parts (`api/`, `web/`, `e2e/`) are separate git repositories — work on a part INSIDE its directory under that part's own AGENTS.md, never from here.

## The rules with teeth

1. **`workspace.json` is the single source of parts.** Never introduce a second list of parts anywhere. Adding or renaming a part means editing the manifest AND the `/<dir>/` block in `.gitignore` in the same change — `pnpm ws:verify` fails when they disagree.
2. **`pairedBrief` is an identity, not a label.** It is the sha256 of the shared brief (recorded in `.prompts/0002-brief.md` on a generated workspace) and every part's `facets.json` must repeat it. Never edit the hash to make `ws:verify` pass — a disagreement means a part answers a different brief, and that is the finding.
3. **The prompt log is append-only** and `scripts/` is the byte-pinned seed (sha256 in `.proto-forge/seed.lock`). A hook blocks edits to both; locks and snapshots are generated (`pnpm snapshot`, `pnpm seed:lock`), never hand-edited.
4. **Every commit names its model, and every dispatch is routed.** Each `.prompts/` entry carries `model: <registered id or alias from .proto-forge/models.json>` — read yours from `.proto-forge/session.json` (the `SessionStart` / `PostModelSwitch` hooks write it) or `PROTO_FORGE_MODEL`, never guess it. An entry written for a dispatched subagent adds `delegated-by: <your entry id>` and `activity: <routing-table key>`, and the subagent runs on the tier the table routes that activity to; a frontier-tier orchestrator delegates only to a strictly cheaper tier, no override, and a deliberate deviation from the routed tier records `routing-override: <reason>`. `prompt:lint` enforces it, and the registry copy is a protected path edited only in the plugin (BR-50, NFR-31).
5. **Relaxing a mandatory gate (`ws`, `snapshot`, `status` — the `MANDATORY_GATES` list in `scripts/config.mjs`) needs a live waiver** in `.proto-forge/config.json` — reason, ADR, expiry. Without one the gate runs at `error` regardless of the config.
6. **The documented status is a derivation.** `docs/STATUS.md`'s block between the quality markers is generated by `pnpm quality:report` from the manifest, the tree and the verify chain; the `status` gate re-renders it byte-wise. Never edit the block by hand — change the source and regenerate.

## When verify is red: `pnpm heal`

`pnpm heal` works a red `pnpm verify` in three bounded tiers. Tier 1 (default on, 2 passes) replays the deterministic regenerations from the healing registry — in this template only the STATUS block (`quality:report`); a manifest/tree disagreement is a decision and deliberately has no recipe. Tier 2 dispatches a bounded agent pass and runs **only** with `selfHealing.agent.enabled: true` in the committed config: committing that flag is the operator's standing, reviewed consent, exactly like `autoPropagate`. Tier 3 prints a blocked report and exits 1. Hard-stop gates never enter any tier, and every pass writes a `.prompts/` entry before it acts.

## Commands

`pnpm verify` is the bar. `pnpm ws:status` for orientation; `pnpm ws:bootstrap` (dry-run) prints how to materialize missing parts; `pnpm ws:up` (dry-run, docker-gated) prints how to start the pair for the e2e part. `pnpm doctor` on a fresh machine — toolchain pins, git presence, every declared part's directory; every ✗ prints its fix. `pnpm quality:report` / `pnpm status:verify` regenerate / verify the derived quality facts.
