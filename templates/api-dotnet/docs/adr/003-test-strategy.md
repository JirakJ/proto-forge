# ADR 003: Total core coverage, mutation testing, and a real database engine in a tool-gated tier

- Status: accepted
- Date: 2026-08-13
- Prompt-log: .prompts/0001-scaffold.md

## Context

Three failure modes make service test suites lie. A coverage floor below 100 on the layers where the product logic lives is a standing licence for untested behaviour exactly where it changes most. 100 % line coverage proves every line ran, not that any assertion would notice a line changing. And a persistence adapter tested against a mock of the database asserts the adapter agrees with the mock — SQL, constraints and ordering stay unproven until production.

## Decision

**Coverage is 100 over line, branch and method on the behavioural core** — the `App.Domain` and `App.Application` namespaces, scoped by coverlet's `Include` filter — enforced live inside `test:unit` by coverlet's `Threshold` with `ThresholdStat` pinned to `total`, and the configuration is part of the contract: `coverage:policy` re-reads the block in `tests/App.Tests/App.Tests.csproj` on every verify and fails a lowered threshold, a dropped counter, a per-module average standing in for the total, an `Include` filter that stops covering the core, and any exclusion that is not on its allow-list with the stated reason on the line above. **The template ships zero exclusions**: the `Include` scope already confines the floors to the behavioural core, and a composition root that needed one is the only entry the allow-list carries. The HTTP and persistence adapters are exercised end to end (the in-memory test host, the native tier) rather than chased to a percentage; the coverlet threshold binds the core, which is where BRS §3.1's argument bites hardest per changed line. When a cobertura report is on disk the gate re-reads it too, so an `Include` filter that quietly widened is caught without waiting a full chain.

**`coverage ignore` markers are a registry, currently empty.** An ignore must state a reason of substance and name the harness case covering the branch in the conformance run (`[covered-by: <case-id>]`, resolved against `tests/App.Tests/Harness/HarnessCases.cs`), and the total count is pinned in the committed snapshot (`ignores` gate).

**Mutation testing proves the assertions fire** (`test:mutation`, Stryker.NET driven by `stryker-config.json`, `break: 85` — the .NET floor recorded here as NFR-14's per-stack extension, ratchet-only). The mutated scope is the behavioural core: `**/Domain/**/*.cs` and `**/Application/**/*.cs`, driven by their own unit suites, with the native and capture tiers filtered out of the mutation run. Transport plumbing (the registrar, the kernel middleware, the EF Core adapter) has a different oracle — the conformance suite and the native tier replaying real exchanges — and mutating it would make the score measure how much plumbing a file contains.

**The persistence adapter is tested against a real engine, in a tool-gated tier.** .NET has no in-process real-Postgres equivalent of PGlite, so the real-database tier is Testcontainers (BRS §15's stated fallback, recorded per stack in §19.9): `tests/App.Tests/Persistence/PersistenceNativeTest.cs` carries the xUnit trait `Category=native`, starts `postgres:16-alpine`, runs `Database.Migrate()` over the committed `Migrations/` history, asserts `HasPendingModelChanges()` is false, and drives the adapter through real SQL — ordering, round-trip and not-found paths. **Docker is absent on some workstations (including the machine this template was built on), so the tier is kept out of every default run by its trait: `test:unit` filters `Category!=native` and the tier is reachable only through `pnpm test:native`, which CI runs unconditionally on a Docker-equipped runner — tool-gated locally, hard in CI, exactly the sec-scan precedent.** No repository mock exists anywhere: the in-memory port fake in `tests/App.Tests/Fixtures/` serves the application layer and the in-memory slices with the same observable semantics, and `stub:scan` bans mocking a first-party type outright, so no substitute for the adapter can appear.

**The tiers are xUnit traits, and the slices boot the real composition.** `native`, `capture` and `conformance` are the three `Category` traits `test:unit` excludes, so the unit run is the fast, database-free one. Everything above it boots `WebApplicationFactory<Program>` (`tests/App.Tests/Slices/SliceAppFactory.cs`) — the exact production wiring, with only the repository port, the clock and the id source swapped for deterministic ones — so what the conformance run and the example capture exercise is the composition root itself, over an in-memory test host with no socket and no database.

**Fixtures are built from the constraints they must not drift from.** `Factory.DefineFactory(...)` runs every produced value through `Validator.TryValidateObject` against the domain's DataAnnotations schema; `stub:scan` rejects a fixtures field that is bare literal data. The e2e conformance run (`test:e2e`) stays a separate pass/fail gate outside the percentage.

**Selftests are two-tier** (BRS §18): Tier 1 (`gates:selftest`) proves every `.mjs` gate on fixture directories in seconds, toolchain-free, with the case-name set byte-identical to api-node's; Tier 2 (`gates:selftest:native`, CI-only) builds throwaway .NET projects and proves the NATIVE halves fire — ArchUnitNET rejects an illegal dependency, the coverlet threshold rejects an uncovered branch, and the EF Core model-agreement proof rejects a model the migrations do not produce — the §19.4/§19.7 precedent, with the tier named explicitly.

## Consequences

"Fully tested" is three mechanical claims — every core line and branch runs, every core assertion bites, every fixture is domain-valid — each with a gate and each with a demonstrated failure case. The costs: wall time for the mutation run (seconds at this size), and the real-database proof landing in CI rather than on a Docker-less workstation — a machine without Docker runs everything else and CI closes the gap on every push.

## Alternatives considered

**Layered 100 on every namespace** — chases percentages on framework plumbing whose oracle is the conformance run, and coverlet cannot cheaply count test-host execution against a second suite. **The in-memory EF Core provider, or SQLite, as a Postgres stand-in** — a mock of a first-party boundary wearing a connection string; banned by BR-12/§15 and rejected outright. **Mocking the repository in adapter tests** — the mock agrees with the mock, which is why `stub:scan` fails a first-party substitute anywhere in the tree. **Mutating everything** — scores plumbing, not behaviour; the narrowed scope is recorded here instead of silently configured.
