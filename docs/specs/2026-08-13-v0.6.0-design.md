# proto-forge v0.6.0 — design: backend templates, CI/CD + DevSecOps, discovery skill

- Status: approved
- Date: 2026-08-13
- Supersedes: — (extends docs/specs/2026-08-12-production-grade-design.md)


## Context

proto-forge (v0.5.0) generuje z briefu production-grade **frontend** prototyp (React 19 + TS + Vite; 24-gate verify, normativní registr s 28 BR/NFR pravidly, citations „no gaps" gate, byte-pinned seed, deterministická pipeline Phase 0–9). Cíl rozšíření: **„zadání + Figma → plně funkční škálovatelná aplikace"** — tři pilíře:

1. **Backendové šablony** — architektura + security jako dva stavební kameny držené celou dobu; enterprise architektury (hexagonální, domain-based/DDD, layered) volené **deterministicky podle komplexnosti**; explicitní best practices; stabilní výstup (stejný brief = stejný výstup i za rok).
2. **CI/CD + DevSecOps** — postupné nasazování; prostředí **local, DEV, SIT, UAT, TEST, PROD** z konfigurace pluginu (early fáze = jen DEV); support skripty pro local i remote env.
3. **Discovery skill (SPIN/DAPA)** — druhý skill: z briefu/Figmy/Confluence vygeneruje gap-analýzu per obrazovka/feature/API oblast — co zákazník skutečně získá + jak se mají chovat nejasné části; s obrázky elementů a pre-alokovanými `data-testid`.

## Pilíř 1 — Backendové šablony

### 1a. Restrukturalizace na registry šablon (základ všeho)

- `git mv template templates/web` + nové `templates/{api-node,api-java,api-python}/`. Přesun **neinvaliduje seed.lock/snapshot** (hash je cwd-relativní — ověřeno v `template-integrity.mjs`).
- Nové **`references/templates.json`**: `{templates: [{id, dir, kind, stack, notAGate[]}]}` — jediný zdroj, přes který iterují plugin gaty. NOT_A_GATE se stěhuje z citations.mjs sem (per template).
- Generalizace hardcodů `"template"`: `scripts/citations.mjs` (TEMPLATE_PKG/SELFTEST → mapy per template; ADR namespace per template — soubor pod `templates/<id>/` cituje default svůj namespace; **ROW_CITE se buduje z parsované tabulky**, řazeno longest-first, už nikdy ruční stropování), `scripts/template-integrity.mjs` (smyčka), `scripts/verify-template.mjs` (`--template <id>`, scratch `.scratch/verify-<id>`), root CI (matrix přes 4 šablony, per-stack setup JDK/uv; Docker na ubuntu-latest pro Testcontainers), `SKILL.md` T1/Phase 0, README, registr — mechanický sweep v témže commitu (citations je checklist).
- **Scope mašinerie citations**: každé pravidlo §10 dostane bullet `**Scope:** all | web | backend | api-node… | plugin` (absence ⇒ `web`, takže 28 stávajících pravidel nevyžaduje okamžitou edici). Check „rule→enforcer" ověřuje skript v package.json **každé šablony ve scope** → stejná jména gatů napříč stacky si vynutí gate sám; check „gate→rule" běží per šablona proti jejímu notAGate; „proven" případy per šablona.

### 1b. Deterministický výběr architektury

- **Facets v2**: `facetsVersion: 2` + volitelné `backend { stack: node|java|python, externalSystems[{name,kind,direction,contract?}], persistence: postgres|none, messaging: none|outbox|broker, authModel: none|apiKey|jwt|oidc }`. Identita briefu = `(facetsVersion, hash)` — novela BR-14; determinismus je slib per verze pluginu (stávající doktrína). **Stack nemá default** — neuvedený = eskalace. Duplikát schématu v každé šabloně `.proto-forge/` drží krok.
- **Skórování** (čisté počty z facetů): E = entity, X = externí systémy, C = komponenty grafu entit (ref-hrany ≈ bounded contexts). Seřazené řádky, první match:
  1. `X ≥ 3 ∨ messaging=broker` → **hexagonální**
  2. `C ≥ 2 ∨ E ≥ 8` → **modulární monolit (DDD)** — modul per komponenta grafu
  3. jinak → **layered** (transaction-script)
- Styl je **odvozený, ne facet**: zapsán do `.proto-forge/architecture.json` `{style, inputs:{E,X,C,flags}}` + ADR 005 šablony; **`arch:verify` derivaci přepočítává** a nesouhlas failuje. Brief vynucující jiný styl = eskalace.
- Decision-table **T14–T22**: T14 výběr targetu (BE-first při páru), T15–T17 tři styly, T18 doménová vrstva per entita, T19 adaptér per externí systém (BR-18 provenance), T20 kontrakt, T21 auth (040–049), T22 eskalace mimo tabulku.

### 1c. Obsah šablon — společná rozhodnutí

- **Jeden skeleton per stack; styl = enforcement profil** (ne 3 skeletony — 9 CI legs zamítnuto). Layout: `domain/ application/ adapters/{in/http,out/persistence,out/<ext>} platform/` + `contract/openapi.yaml` + `db/migrations/` + `src/harness/` (registry scénářů endpoint×stav — čistá data, konzumovaná docs:examples i generovaným e2e; parita 2×).
- **Gate korpus zůstává Node .mjs i pro Java/Python** — nativní toolchain (Gradle/uv) dělá build/test/coverage/mutation/arch, orchestruje `pnpm verify`; neutrální gaty (config, selftest harness, adr-lint, prompt-lint, stub-scan, snapshot-diff, sec-scan, outbox…) se kopírují. Cena: generovaný Java/Python repo potřebuje node+pnpm (pinned, ADR 009 šablony). **Klíčové rozhodnutí — citations funguje beze změny tvaru.**
- **Byte-pinned seed per BE šablona** = `scripts/` + `platform/` kernel (problem-details RFC 9457, logging s PII redakcí, security headers, health) — stejná seed.lock mašinerie + guard hook.
- Demo: **Note CRUD service** (stejná doména jako FE demo → pár demonstruje FE↔BE kontrakt), mazané ve Phase 1.
- **BE nepřekládá** — ekvivalent i18n = **katalog chyb** (stabilní problem-type URI): gate `error:catalog`.
- Mapování gatů FE→BE: layer:scan→**arch:verify**, testid:scan→**opid:scan** (unikátní deterministické operationId `<resource>-<verb>`, route registry místo literálů), overlay:matrix→**contract:conformance** (v test:e2e), docs:shots→**docs:examples** (zachycené request/response příklady, `example.lock` freshness hash), budget→**deps:budget**, + nové **migration:verify** (append-only, model↔migrace shoda), **contract:verify** (regen+normalize+diff+lock) a **contract:breaking** (pinned oasdiff; breaking bez major bump+ADR failuje), **log:scan**.

### 1d. Per stack

| | api-node | api-java | api-python |
|---|---|---|---|
| Piny | node 22, Fastify 5, zod, Drizzle, pino, jose | JDK 21, Gradle wrapper checksum-pin + dependencyLocking, Spring Boot 3.5.x, Flyway, JPA, springdoc | Python 3.12, uv+uv.lock, FastAPI+Pydantic v2, SQLAlchemy 2+Alembic, ruff, mypy --strict, structlog |
| arch:verify | eslint-plugin-boundaries (3 profily) | **ArchUnit** (Modulith zamítnut) | **import-linter** |
| Kontrakt | zod→OpenAPI, lock+diff | springdoc v test slice + **sdílený normalizér** (`scripts/contract-normalize.mjs`) | nativní `app.openapi()` |
| Coverage | 100 % domain+application, 90 adaptéry (coverage-policy reuse) | JaCoCo per-package + exclusion registry | port coverage-policy nad coverage.json |
| Mutace | Stryker **break 90** | PIT **break 85** + ratchet | mutmut **break 85** + ratchet |
| DB testy | Testcontainers Postgres (reálná DB — BR-12, žádné pg-mem) | Testcontainers + flyway validate | Testcontainers-python |
| Security | helmet, pnpm audit, CycloneDX | Spring Security, SpotBugs+findsecbugs, OSV-Scanner nad SBOM | pip-audit, bandit, cyclonedx-py |

- **gates-selftest dvouúrovňový**: Tier 1 (vteřiny, ve verify — fixture adresáře pro .mjs gaty), Tier 2 **`gates:selftest:native`** (CI-only — throwaway Gradle/pytest projekty; precedent §19.4/§19.7, „Proven by" jmenuje tier explicitně).

### 1e. Kontrakt FE↔BE (oddělené repozitáře)

- Kanonický domov: BE repo `contract/openapi.yaml` + `contract.lock` (sha256 + contract SemVer), re-lock ve stejném ADR commitu jako změna kódu.
- FE: kontrakt zaznamenán přes BR-18 (`docs/external/api-contract/`), klient generován pinned `openapi-typescript`, nový web gate **`contract:client`** (lock klienta == sha256 záznamu); MSW handlery zrcadlí záznam.
- Orchestrace (T14): jeden brief → **BE první** (vyprodukuje kontrakt), pak FE; oba repos nesou `pairedBrief` hash ve facets.json.

### 1f. SKILL + ADR

- Hlavní skill: **Phase 0 rozhodne target(y)** (web / api-<stack> / oba, BE-first); fáze 1–9 drží čísla i gate disciplínu, obsah se větví (BE: 1 scaffold+architecture.json, 2 doména, 3 kontrakt+adaptéry+migrace, 4 endpoint/use-case DoD, 5 error katalog+observabilita, 6 testy, 7 security, 8 docs:examples+sweep, 9 release+publikace kontraktu).
- Pre-written ADRs 001–009 per BE šablona (005 = architektura s generation-time slotem pro odvozený styl); demo ADRs 010/022/030 mazané s demem; MANDATORY_GATES per šablona (`arch, contract, errorCatalog, migration, opid, …`).

## Pilíř 2 — CI/CD, DevSecOps, prostředí

### 2a. Principy

1. **Verify zůstává offline** — nic ve verify neotevírá socket; externí binárky dle gitleaks vzoru (enforce když je, note lokálně, hard-fail v CI). Vendorované kubeconform schemas + semgrep rules (`.semgrep/`).
2. **BR-20 se rozšiřuje na clustery** (→ BR-28): operátorský deploy je staged-first (`render` do outboxu) přes `assertMayDeploy` (zrcadlo assertMayCommit dveře-za-dveřmi + `currentContextMatches` — odmítne cizí kubectl context); CI konsent = committed workflow + GitHub environment required reviewers (preflight přes GH API ověří, že `approval: required` v configu má protection rules).
3. **Jeden zdroj pravdy**: `environments{}` v configu je jediná deklarace; values soubory, cd plan, DEPLOYMENT.md tabulka se derivují/kontrolují (BR-27).
4. **Deploy nastavení nejsou facety** — nevstupují do facet hashe (BR-14); šablona shipuje kompletní verify-green deploy surface s **jen `dev.enabled: true`**; zapnutí SIT/UAT/TEST/PROD = reviewovaný config diff, nikdy regenerace.

### 2b. Konfigurace

- `config.schema.json` + DEFAULTS: **`environments`** jako objekt s fixními klíči (local/dev/sit/uat/test/prod — objekt kvůli deep-merge; pořadí je konstanta `ENV_ORDER` v config.mjs; promoční řetězec = enabled remote envs v ENV_ORDER, derivace `promotionChain(cfg)`), per env `{enabled, url, cluster{type: openshift|aks|generic, server, namespace, registry}, approval: none|required, autoDeploy (analog autoPropagate — nahrazuje jen --approve), auth{method: oidc|token|kubeconfig, *Env jména}}`; **`deployment`** `{flavor: helm|compose, imageRegistry, sign, scan{image, severityThreshold}, helm{chartPath, keepHistory}}`.
- `checkConfig` nová pravidla: local povinný; enabled env musí mít namespace+type; **prod nesmí být první enabled env**; prod `approval: none` = hard error; `*Env` hodnoty musí vypadat jako jména env proměnných (`^[A-Z][A-Z0-9_]*$`) — mechanické „žádné secrets v configu"; compose flavor + multi-env = error; warning na server mimo network allowlist.
- `guardrails.requireApproval` default += `deploy.dev`…`deploy.prod`. Secrets kontrakt žije jen ve values (`envFromSecrets:` jména) — žádný duplikát v configu (BR-15).

### 2c. Artefakty per aplikace (seed šablon, ne generované fázemi)

- `Dockerfile` (multi-stage, non-root, **arbitrary-UID-safe** — group-0 práva; FE: `nginx-unprivileged` pinned digestem, port 8080, strict CSP z SECURITY.md v `deploy/nginx/default.conf`; BE: node:22-slim / ubi9-openjdk-21 / python:3.12-slim), `GIT_SHA` → `version.json` pro smoke.
- `deploy/compose/docker-compose.yml` (local; BE + postgres s healthcheckem), `deploy/chart/` (jeden chart, values per env — **values soubor existuje jen pro enabled env**; securityContext kontrakt: runAsNonRoot, žádný runAsUser, drop ALL, seccomp, readOnlyRootFilesystem; `expose.kind: route|ingress|none` cross-checked proti `cluster.type`; NetworkPolicy default-deny; PDB při replicas>1), `deploy/schemas/` (vendorovaný kubeconform), `deploy/smoke.mjs` (GET /version + headers, assert SHA).
- HSTS na TLS edge (Route/Ingress anotace) — v souladu s poctivým CSP příběhem z v0.5.0.

### 2d. Pipelines (statické workflows + config-driven skip — ne generované matice)

- **`package.yml`**: po zeleném verify na main / na tag: buildx (GIT_SHA) → trivy (HIGH/CRITICAL, exit 1) → image SBOM → push (GHCR přes GITHUB_TOKEN; ACR přes azure/login OIDC) → cosign keyless sign + SBOM attest.
- **`cd.yml`**: `plan` job čte config → outputs enabled flagů; push na main → jen dev; tag `v*` → celý řetězec dle ENV_ORDER; per env job: `environment:` (GH protection = lidský approval), approval-preflight (GH API), cosign verify identity workflow, cluster login per type (aks OIDC / oc token / kubeconfig), `helm upgrade --install --atomic --history-max`, smoke. Skip-sémantika: `!failure() && !cancelled()` + enabled flag (efektivní předchůdce z plan outputs). Rollback: --atomic + `env:remote rollback` (helm rollback, okno keepHistory=5).
- `verify.yml` beze změny obsahu + `workflow_call:` trigger + pinned tool installs. DevSecOps stage tabulka (verify→package→deploy dev→promote) jde do DEPLOYMENT.md. Pinned `actionlint` do plugin verify.

### 2e. Gaty, skripty, docs

- Nové **mandatory** gaty (web: 13→15; BE šablony je mají v seznamu od začátku): **`env:verify`** (env.example ≡ EnvSchema parita; žádné secret-shaped hodnoty; enabled env ⇔ values soubor — obousměrně; DEPLOYMENT.md env tabulka mezi markery ≡ derivovaná, `--write` regeneruje) a **`deploy:verify`** (nativní: Dockerfile pinned digest/no ADD-URL/no secrets v ENV; compose healthchecky; values resources+probes+securityContext; Route↔type shoda; `.trivyignore` disciplína `# reason … until:`; tool-gated: compose config -q, helm lint+template→kubeconform, hadolint, rendered asercí securityContext).
- Support skripty (vše node .mjs): **`env:local`** (init/up/down/status/seed — compose --wait, bez approval dveří), **`env:remote`** (check/render/diff/bootstrap/deploy/rollback/status — render offline do outboxu; bootstrap renderuje namespace/quota/networkpolicy/SA/**Secret skeletony (hodnoty REPLACE_ME) — Secrets se NIKDY neaplikují**, ani s --commit --approve; tiskne `oc/kubectl create secret` a `gh api` příkazy pro GH environment protection), sdílený **`deploy-lib.mjs`** (assertMayDeploy + currentContextMatches).
- Docs: **`DEPLOYMENT.md`** (env tabulka gate-synced, promoce, DevSecOps stage tabulka, secrets kontrakt, runbook, OpenShift-vs-AKS poznámky, compose appendix), SECURITY.md += pipeline/supply-chain sekce, ARCHITECTURE.md += CI/CD. `sec-scan.mjs` += semgrep (vendorované rules).
- **Multi-template**: plugin-level **`shared/deploy/`** (kanonické kopie env/deploy skriptů, workflows, chart templates, schemas) + plugin gate **`deploy:sync`** — byte drift kopie v šabloně proti shared failuje; per-template povolené odchylky deklarované (Dockerfile, values, probe cesty).

## Pilíř 3 — Discovery skill (`proto-forge:discovery`)

### 3a. Zapojení druhého skillu

- **`skills/discovery/`**: `SKILL.md` (frontmatter `name: discovery`; popis ~1050 znaků s CZ+EN triggery: /discovery, „gap analýza", „SPIN", „co zákazník vlastně chce"…), vlastní `skill.json` (verze == root), `references/` (**discovery-table.md D1–D9**, document-template.md, testid-derivation.md, figma-contract.md), **mini-template `skills/discovery/template/`** (copy-first per run): `.discovery/lint.mjs` (dependency-free, argv[2] = cílový adresář), `questions.json` (Q1–Q24), `discovery.schema.json`, self-verifying sample dokument.
- `plugin.json` → `"skills": ["../..", "../../skills/discovery"]` — manifest-lint beze změny (pole už iteruje). Resolvuje se jako `proto-forge:discovery` (jméno z frontmatteru).
- **Generalizace `skill-lint.mjs`**: smyčka přes `plugin.json skills[]` jako jediný registr; per skill SKILL.md+skill.json, shoda jmen, kebab gramatika, unikátnost, basename==name (kromě root), verze==root; pointer-scan += `walk("skills")`. Selftest fixtures dostanou explicitní plugin.json.
- `citations.mjs`: SCANNED_TREES += `skills`; nové **D-** a **Q-** citační namespacy (bounded, jen .md).

### 3b. Pipeline D0–D4

- **D0 intake**: kopie mini-template do `./discovery/` (nebo `docs/discovery/` uvnitř generovaného repa — detekce `.proto-forge/`); vstupy verbatim do `.inputs/`; smazání sample; **inventory.json** — jednotky `{id, kind: screen|feature|api-area, order, sources[]}` fixními pravidly (Figma top-level frame → screen; flow bez frame → feature; entita/externí systém → api-area); hash inventáře = identita discovery.
- **D1 elementy**: Figma `get_metadata` → tabulka elementů; **deterministické testidy** `<unit-id>-<slug(layer)|role>` + kolizní `-n` dle node order (gramatika == testid-scan); api-area: `api-<unit>-<verb>-<resource>` (konzumuje operationId pilíře 1). `get_screenshot` → `images/` + **images.lock** (fileKey, nodeId, fileVersion, sha256, capturedAt — analog .shot.lock).
- **D2 gap detekce**: fixní taxonomie **Q1–Q24** (screen: error/empty/loading/permissions/validace/confirm/i18n/overflow; feature: actor+trigger/done/failure/side-effects; api-area: endpointy/**data ownership**/authz/error kontrakt/paginace/idempotence/lifecycle-PII/**integrační kontrakt**; cross-cutting: business value→Need-payoff, rollout→pilíř 2, locales, offline/realtime→facety). Každý gap nese **konzervativní default**; klasifikace answered/gap musí citovat evidenci.
- **D3 dokument per jednotka** (anglicky): frontmatter (id/kind/status/gapsOpen/gapsTotal/sources s pinningem), **SPIN** (Situation s evidencí / Problem / Implication vázané na gap čísla / Need-payoff = co zákazník získá), **DAPA = Definition / Acceptance criteria / Prerequisites / Assumptions** (dokumentová reinterpretace — sign-off vyplněním Answer sloupce; Assumptions = stojící konzervativní defaulty), tabulka Elements, **Gap table** (8 sloupců, Answer prázdný). Chybějící obrázek = `<!-- no-image: reason -->`.
- **D4 bridge**: `discovery.json` regenerovaný z dokumentů (jednosměrně; lint hlídá shodu): units+statusy, `testids[]` (rezervace), `gaps[]`, **`facets` prefill fragment** (jen kde zdroje odpověděly); „consolidate" mód po doplnění odpovědí.
- **Napojení na hlavní skill (Phase 0)**: existuje-li discovery.json — hash do `.prompts/0003-discovery.md`; facets fragment = výchozí bod normalizace (brief vyhrává, konflikt = eskalace); `testids[]` = rezervované alokace pro Phase 4 DoD; dokumenty se kopírují do `docs/discovery/**`. **BR-14/facet hash nedotčen** — provenance v prompt logu.
- Determinismus poctivě: pinned strom/idy/testidy/otázky/tvary; próza SPIN/DAPA vázaná pravidly; Figma bajty pinned záznamem (ne reprodukcí); timestampy jen jako provenance, žádný gate nečte hodiny. Figma **nikdy povinná** (brief-only mód).

### 3c. Gate

- **`discovery:lint`** — jedna implementace, dvě volací místa (plugin verify nad shipped mini-template; runtime nad výstupem): frontmatter, přesné sekce, well-formed gap tabulka (Q-id resolvuje, evidence+default neprázdné), testid gramatika + unikátnost napříč dokumenty, obrázky existují + sha256, počty přepočítané, docs↔inventory↔bridge parita, `status: answered` ⇔ všechny Answer vyplněné. Přidán do root `verify`. `scripts/discovery-lint.selftest.mjs` (~15 případů, auto-discovery přes selftest-all).

## Doplněk 2026-08-13 (2): E10 — known-issues prevence + auto-generovaný quality status

Operátorský požadavek: ošetřit common known issues during development and testing
(„aby něco nefungovalo" se nesmí stávat) a dokumentace musí automaticky nést počty
prováděných testů atd. — stav kvality viditelný z pohledu CI/CD i pro generované
aplikace.

**E10a — quality status (BR-36):** test-tier gaty každé aplikační šablony zapisují
strojová fakta do `.proto-forge/quality.json` během verify (unit počty + coverage %
z json-summary/coverage.json/JaCoCo, mutační skóre, počty e2e/konformančních
scénářů, počet gatů); `quality:report` z něj generuje blok `docs/STATUS.md` mezi
markery (bez wall-clocku — čerstvost = svázání s týmž verify během); nový mandatory
gate `status:verify` hlídá shodu dokumentu s quality.json a quality.json s
konfigurací (prahy, seznam gatů). CI: verify workflow přidává tabulku do
`$GITHUB_STEP_SUMMARY` a nahrává quality.json jako artefakt.

**E10b — known-issues prevence (NFR-18):** `pnpm doctor` per šablona (notAGate):
piny toolchainu vs instalace, husky hooky, shoda nainstalovaného stromu s lockfile
(třída stale-.pnpm incidentů), stale `.stryker-tmp`, obsazené porty, přítomné
prohlížeče, env soubor. Determinismus: TZ=UTC + LANG pinned v test konfiguracích.
`docs/TROUBLESHOOTING.md`: kurátorovaný katalog symptom→příčina→oprava známých
selhání (stale mutation cache, stale installed copies, docker-absent tiery,
EADDRINUSE, chybějící browsery, gradle wrapper first-run, uv python fetch, husky po
klonu…). Referenční implementace web+api-node, poté propagace na zbylé šablony;
`deploy:sync`-style byte-sdílení tam, kde je korpus stejný.

## Doplněk 2026-08-13 (3): E10c — self-healing agent loops

Operátorský požadavek: agentní smyčky pro self-healing. Design váže na existující
doktrínu (gate-failure protokol, append-only prompt log, konsent BR-20 rodiny,
guard hooky mrazící floory):

**Třívrstvé hojení (`pnpm heal`, scripts/heal.mjs v aplikačních šablonách):**
1. **Tier 1 — mechanická regenerace (default zapnuto):** verify → na červený gate
   se aplikuje deterministická oprava z HEALING REGISTRY (data, ne heuristika):
   stale screenshoty → `docs:shots`; stale examples → `docs:examples`; stale
   STATUS → `quality:report`; drift klienta → `contract:client:generate`; drift
   kontraktu (BE, po reviewed změně kódu) → `contract:generate`; stale mutation
   cache → vyčištění `.stryker-tmp`; lockfile-vs-tree drift → čistá reinstalace.
   Snapshot/seed NIKDY (konsentní akty). Max passes z configu (default 2), každý
   pass zapsán do `.prompts/` PŘED provedením.
2. **Tier 2 — agentní smyčka (default VYPNUTO, committed consent):**
   `selfHealing.agent.enabled: true` v configu = revidovaný souhlas (vzor
   autoPropagate/autoDeploy). Dispatch agenta (konfigurovatelný příkaz, default
   `claude -p`) s výstupem gatu, gate-failure pravidly (smí jen přidávat
   testy/překlady/testidy/docs nebo opravit flagged řádek; floory mrazí guard
   hooky tak jako tak), TROUBLESHOOTING + doctor kontextem; max passes (default
   2); každý pokus prompt-logged před spuštěním. **Hard-stop gaty (secrets,
   high/critical audit, contradiction) do smyčky NIKDY nevstupují.**
3. **Tier 3 — eskalace:** run končí `blocked` v snapshot.gates, jmenuje gate +
   poslední prompt-log entry (stávající sémantika).

**CI:** volitelný `heal.yml` (workflow_dispatch; volitelně workflow_run po
červeném verify): bez agentního konsentu jen Tier 1 (mechanické regeny) + PR
s výsledkem; Tier 2 v CI vyžaduje `selfHealing.ci.enabled` + committed consent.

**Config:** nový blok `selfHealing {mechanical {enabled: true, maxPasses: 2},
agent {enabled: false, maxPasses: 2, commandEnv?}, ci {enabled: false}}` +
checkConfig validace mezí. **Norma NFR-19 — „Self-healing je vrstvené,
ohraničené a na záznamu"**: Enforced by `config:check` (konsent/meze) + guard
hooky; Proven by heal selftesty („heal: a mechanical drift heals in one pass",
„heal: a hard-stop gate is never healed", „heal: the agent tier without
committed consent is refused", „heal: every pass writes a prompt-log entry
first", „heal: passes stop at the configured bound"). `heal` = notAGate.
Referenčně web+api-node, pak jedna propagační vlna E10a+b+c na zbylé šablony.
