# ADR 003: Total core coverage, mutation testing, and a real database engine in a tool-gated tier

- Status: accepted
- Date: 2026-08-13
- Prompt-log: .prompts/0001-scaffold.md

## Context

Three failure modes make service test suites lie. A coverage floor below 100 on the layers where the product logic lives is a standing licence for untested behaviour exactly where it changes most. 100 % line coverage proves every line ran, not that any assertion would notice a line changing. And a persistence adapter tested against a mock of the database asserts the adapter agrees with the mock — SQL, constraints and ordering stay unproven until production.

Kotlin adds a fourth, specific to this stack: a JVM coverage tool and a JVM mutation tool both see the *compiler's* output, not the source. Generated members and compiler-inserted intrinsics land inside the measured packages, and neither tool can tell them from code somebody wrote. Left alone they either force a floor down or make a score meaningless. Both are handled here, on the record, and neither by lowering a number.

## Decision

**Coverage is 1.00/1.00/1.00 (INSTRUCTION/BRANCH/LINE) per package on the behavioural core** — `app.domain` and `app.application`, every subpackage — enforced by `jacocoTestCoverageVerification`, and the configuration is part of the contract: `coverage:policy` fails a lowered minimum, a rule that stops covering the core packages, and any `classDirectories` exclusion that is not on its allow-list with the stated reason on the line above. The exclusions are the composition roots only (`MainKt`, `WiringKt`, `MigrateMainKt` — covered by the conformance run). The http and persistence adapters are exercised end-to-end (the `testApplication` conformance replay, the native tier) rather than chased to a percentage; the JaCoCo rule binds the core, which is where BRS §3.1's argument bites hardest per changed line.

**The domain's wire schemas are hand-written serializers, and that is a coverage decision as much as a design one.** A `@Serializable` class whose properties carry no defaults makes the kotlinx plugin emit a synthetic constructor with a missing-field branch that *no* kotlinx decoder reaches — both the streaming and the tree JSON decoders reject an incomplete document before it — so the branch is dead bytecode inside a package whose floor is 1.00. Measured, it costs 6 % of instructions and 25 % of branches on `app.domain.note`. The template does not exclude it and does not lower the floor: `Note` and `NoteCreate` declare `@Serializable(with = …)` and their `KSerializer`s are written out in `NoteWire.kt`, which deletes the generated code, makes every remaining line something a reviewer can read, and turns "which field is missing" into a message this template owns and its tests can reach. The allow-list in `coverage:policy` therefore carries no serialization entry at all — the exception it would have held is absent by construction.

**`jacoco ignore` markers are a registry, currently empty.** An ignore must state a reason of substance and name the harness case covering the branch in the conformance run (`[covered-by: <case-id>]`), and the total count is pinned in the committed snapshot (`ignores` gate).

**Mutation testing proves the assertions fire** (`test:mutation`, PIT, `mutationThreshold = 85` — the JVM floor from NFR-14, ratchet-only, reflecting PIT's weaker operator set against Stryker's 90). The mutated scope is the behavioural core: `app.domain.*` and `app.application.*`, driven by their own unit suites. **PIT is told to leave the Kotlin compiler's null-check intrinsics alone** (`avoidCallsTo` adds `kotlin.jvm.internal.Intrinsics` to PIT's defaults). This is not a narrowed scope — every class above is still mutated — it stops the VOID_METHOD_CALLS mutator from deleting `Intrinsics.checkNotNullExpressionValue` calls the compiler inserts on platform-type boundaries. Those mutants are unkillable by construction in Kotlin-only code: no test can make a Kotlin non-null expression null, so a surviving one measures the compiler and then blames the suite for it. **The numbers, both ways: without the filter PIT generated 29 mutations and killed 22 (76 %), and all 7 survivors were that one intrinsic; with it, 20 mutations, 20 killed, 100 %.** Transport plumbing (the registrar, the problem pages, the Exposed adapter) has a different oracle — the conformance suite and the native tier replaying real exchanges — and mutating it would make the score measure how much plumbing a class contains.

**The persistence adapter is tested against a real engine, in a tool-gated tier.** The JVM has no in-process real-Postgres equivalent of PGlite, so the real-database tier is Testcontainers (BRS §15's stated fallback, recorded here in the spirit of §19): `PersistenceNativeTest` (tag `native`, `./gradlew nativeTest`) runs the committed history against `postgres:16-alpine`, reads the live catalog back to prove the Exposed table matches the schema Flyway produced, and drives the adapter through real SQL. **Docker is absent on some workstations (including the machine this template was built on), so the tag is excluded from `test` and CI runs `nativeTest` unconditionally on a Docker-equipped runner — tool-gated locally, hard in CI, exactly the gitleaks precedent.** No repository mock exists anywhere: the in-memory port fake in the `app.fixtures` test package serves the application layer and the `testApplication` slices, with the same observable semantics, and is itself never a stand-in for the adapter.

**Fixtures are built from the constraints they must not drift from.** `Factory.defineFactory(check, defaults)` validates every produced value through the domain's own `violations()`; `stub:scan` rejects a fixtures-package constant that is bare literal data. The e2e conformance run (`test:e2e`) stays a separate pass/fail gate outside the percentage.

**Selftests are two-tier** (BRS §18): Tier 1 (`gates:selftest`) proves every `.mjs` gate on fixture directories in seconds, JVM-free, with the case-name set byte-identical to api-node's and api-java's; Tier 2 (`gates:selftest:native`, CI-only) builds throwaway Kotlin Gradle projects and proves the NATIVE halves fire — ArchUnit rejects an illegal import, the JaCoCo rule rejects an uncovered branch, `flyway validate` rejects a drifted migration — the §19.4/§19.7 precedent, with the tier named explicitly.

## Consequences

"Fully tested" is three mechanical claims — every core line runs, every core assertion bites, every fixture is domain-valid — each with a gate and each with a demonstrated failure case. The costs: hand-written serializers are ~70 lines the compiler would otherwise have produced (and their own tests), wall time for PIT (seconds at this size), and the real-database proof landing in CI rather than on a Docker-less workstation.

## Alternatives considered

**Leaving `@Serializable` to the plugin and excluding the generated members** — JaCoCo excludes whole class files, and the generated constructor lives *on* the data class, so the exclusion would take the real code with it. **Lowering the floor to 0.94 for `app.domain`** — the exact silent erosion the gate exists to stop. **Calling the synthetic constructor by reflection to colour the counter in** — a test that exists to satisfy a number. **Layered 100 on every package** — chases percentages on transport plumbing whose oracle is the conformance run. **An embedded/H2 stand-in for Postgres** — a mock of a first-party boundary wearing a JDBC url; banned by BR-12/§15. **Mocking the repository in adapter tests** — the mock agrees with the mock. **Mutating everything** — scores plumbing, not behaviour.
