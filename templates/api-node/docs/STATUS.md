# Quality status

This page carries the measured quality facts of the service: how many unit
tests and conformance scenarios ran and passed, what the coverage actually is
on each of the four axes, how hard the suite bites (the mutation score), how
many operations and problem types the committed contract carries, and which
gates stand in the `pnpm verify` chain. Nothing between the markers is typed by
hand — the table is regenerated by `pnpm quality:report` from
`.proto-forge/quality.json`, which the test tiers' own reporters fill during
`pnpm verify`, and the mandatory `status` gate fails the build the moment this
document, the machine facts and the enforcing configuration disagree. There are
deliberately no dates on this page: freshness is not a timestamp, it is the
bond to the same verify run — when a number changes, the diff of this file
shows it.

The floors and counts in the table are mirrors, not sources: the coverage
floors live in `vitest.config.ts` (held to 100 by `coverage:policy`), the
mutation break in `stryker.config.json`, the gate chain in `package.json`'s
`verify` script, and the operation and problem-type counts in
`contract/openapi.json` and `src/platform/problems.ts`. `pnpm status:verify`
re-reads all of them and fails when a mirror and its source drift apart, so the
one command that refreshes everything is a full `pnpm verify` — or
`pnpm quality:report` alone when the reports are already on disk from the run
you are documenting.
